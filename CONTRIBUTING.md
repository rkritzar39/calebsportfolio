# Contributing to Caleb's Portfolio

Thank you for your interest in contributing to **Caleb's Portfolio**.

This repository contains the source code for Caleb Kritzar's personal portfolio website. The portfolio presents projects, skills, experience, education, technology interests, and other professional information.

Contributions that improve performance, accessibility, compatibility, maintainability, or the overall user experience are welcome. However, because this is a personal portfolio, changes to personal information, branding, featured projects, written content, and design direction remain under the control of the repository owner.

## Code of Conduct

Everyone participating in this project is expected to communicate respectfully and constructively.

When contributing:

- Be respectful toward other contributors.
- Provide clear and useful feedback.
- Focus criticism on the code or proposal rather than the person.
- Do not submit harassment, spam, discriminatory content, or malicious code.
- Do not intentionally expose private or sensitive information.
- Respect the repository owner's final decisions regarding the portfolio's content and design.

Unacceptable behavior may result in the removal of comments, issues, pull requests, or access to the repository.

## Ways to Contribute

You can contribute by:

- Reporting a reproducible bug.
- Fixing layout or responsive design problems.
- Improving keyboard navigation.
- Improving screen reader support.
- Correcting accessibility violations.
- Improving website performance.
- Fixing browser compatibility problems.
- Correcting spelling or grammar errors.
- Improving documentation.
- Simplifying or refactoring code.
- Adding tests.
- Suggesting a feature or user experience improvement.
- Reporting a security or privacy concern.

Changes to personal biography information, project history, social links, education information, device information, branding, or portfolio claims should not be submitted unless requested by the repository owner.

## Before You Begin

Before opening an issue or pull request:

1. Search the existing issues to determine whether the topic has already been reported.
2. Check existing pull requests for related work.
3. Confirm that the problem still exists in the latest version of the default branch.
4. Collect clear reproduction steps, screenshots, browser information, and device information when relevant.
5. Keep the proposed change focused on one problem or feature.

Do not combine unrelated fixes into a single pull request.

## Development Setup

### Prerequisites

Install the tools required by the project before beginning.

Depending on the current project configuration, this may include:

- https://git-scm.com/
- [Node.js](https://nodejs.org/)
- npm, pnpm, or another package manager specified by the repository
- A modern code editor such as Visual Studio Code
- A modern browser with developer tools

Use the package manager already configured in the repository. Do not replace the existing lockfile or introduce a different package manager without approval.
